## 0. 范围和红线

- **只改界面**：菜单位置、顺序、名称、快捷键、工具栏、右键菜单、编辑面板和波形工具条的分组与排列、主窗口工具栏。
- **不改**：业务逻辑、撤销记录、工程格式（FORMAT-v1）、导出结果（发布 ASS、整季、参考导出、审议包）字节不变、设置里已有的键名和含义。
  已有的 QSettings 键（布局、打轴方式、显示规则、各面板开关等）原样读写，旧用户升级后看到的状态和以前一样。
- 每个动作的处理函数不变（菜单、按钮、右键、快捷键都调用现在的同一个函数），只换"从哪里触发"。
- 四种布局（视频优先／列表优先／左右分栏／卡拉 OK）保留，名称、切换方式和分割比例算法不变。
- 对话框内部（新建工程、合并设置、导出、读音弹窗等）本轮不动，只有 §11 列出的几处文字统一。
- 输入法、焦点、字幕命中、全屏、取消／关闭和后台任务生命周期的现有行为是验收项，不是可以顺手改的地方。

## 1. 原则

1. **按"我现在要做什么"分组**，顺序大致是工作流：工程和集 → 改字幕 → 调时间 → 注音 → 播放 → 看 → 输出规则 → 工具。
2. **一个动作一个名字**：菜单栏、右键菜单、按钮、悬停提示、状态栏提示和说明书写法一致。快捷键是真正的快捷键，菜单里右侧显示；**不再把键写进文字**（去掉「播放本组（S）」「自由变换\tT」这类写法）。
3. **右键菜单是菜单栏的子集**，同一个动作对象，顺序固定：常用、无害在上，删除在最下面并用分隔线隔开。
4. **不适用就不显示，条件不够才变灰**：和当前对象无关的项（例如对白组的「K 轴特效」、没有原声时的「只删原声」）直接不显示；
   "能做但现在条件不够"的项变灰，并在文字后保留现在的原因写法「（先打开一集）」「（先选中字幕组）」。
5. **低频功能进「工具」**，按用途分子菜单。顶层菜单每个不超过约 12 项，子菜单最多两层。
6. **所有命令都在动作注册表里**（§9），有固定 ID、名字、默认键、场景和说明书锚点；按钮和菜单从注册表取同一个 QAction。

4. **操作区**（不截断文字，允许分两行，按组整体换行）：
   - 第一组「分界」：「开头一段 → 上一组」「结尾一段 → 下一组」「拿回上一组结尾一段」「拿回下一组开头一段」

## 9. 快捷键

### 9.1 现状（盘点结论）
三种实现：菜单 QAction 自带键；`_build_shortcuts` 里的窗口级 QShortcut（菜单看不到）；eventFilter 和控件 keyPressEvent 里硬编码的键（Z/X、T、Shift+K、Del 删空拍、Enter/Esc 采用建议、F1、按住 K）。
单字母键（R、S、Q、W、D、E、C、[、]）在输入框里不响应，靠的是 Qt 文本框对可打印键的 ShortcutOverride（C 另外有 `_typing()` 判断）。

### 9.2 动作注册表（新模块 `src/subkit_app/actions.py`）
每个动作一条记录：

| 字段 | 说明 |
|---|---|
| `id` | 稳定 ASCII ID（如 `group.merge`），设置和测试用它；以后不改 |
| `text` | 菜单上的名字（本文 §3 的文字） |
| `keys` | 按场景的默认键：`{scene: [主键, 次键…]}`；菜单显示当前场景的主键 |
| `help_anchor` | 说明书锚点 |
| `typing` | 输入框有焦点时是否响应（`False`＝不响应，等同现在的 `_typing()` 判断；Ctrl+R、Ctrl+Space 这类为 `True`） |
| `customizable` | 是否出现在「快捷键…」里（弹窗内部键为 `False`） |

场景：

| 场景 ID | 中文名 | 何时有效 |
|---|---|---|
| `main` | 编辑界面 | 主窗口，不在观剧模式 |
| `watch` | 观剧模式 | F10／F11 时；没有单独绑定的动作沿用 `main` 的键 |
| `k` | K 轴 | 选中歌曲组且焦点在主窗口；只有 K 轴动作 |
| `popup` | 弹窗内部（固定） | 读音弹窗、就地编辑、自由变换中；不能改，只在一览里列出 |

一个动作可以有多个键（Ctrl+Enter／Ctrl+Return、Ctrl+Y／Ctrl+Shift+Z、Shift+[／{、R／Ctrl+R）。
按场景不同的键：←／→ 和 Ctrl+←／→ 在 `main` 与 `watch` 互换（现状），注册表按场景各写一份默认值。
优先级（现状）：`popup` > `k`（选中拍或有建议时的 Del、Enter、Esc、Shift+K）> `watch` > `main`。

### 9.3 实现约束
- 菜单项、工具栏按钮、右键菜单、编辑面板按钮从注册表拿**同一个 QAction**（右键菜单可以临时改文字加原因，但触发同一个处理函数）。
- `_build_shortcuts` 里的 QShortcut 全部改为注册表动作的快捷键；eventFilter 里的模式键（Z/X、T、Shift+K、K 跟唱）改为"比较注册表里当前绑定的键"，不再写死 `Qt.Key_*`，处理逻辑和判断条件（是否在打字、是否有弹窗、自由变换中等）一字不改。
- `popup` 场景的键（Enter、Esc、Tab、1–9、方向键、Alt+←→、Backspace、3）不进自定义，写在一览里。
- **保留键**（不能分配给任何可自定义动作）：F1、Esc、Tab、Shift+Tab、Enter（不带修饰键）、Alt+F4、Alt 单键、Win 键组合、Ctrl+A/C/V/X（输入框编辑）、输入法切换键（Ctrl+Space 除外——它现在就是"播放／暂停"，照旧）。
- 单字母或不带 Ctrl/Alt 的键分配给 `typing=False` 以外的动作时，「快捷键…」里提示「这个键在输入框里打字时会被当成文字，不会触发」。

### 9.4 默认键变化（新旧对照）
**现有的键全部保留，不改含义。** 只给常用但没有键的命令补默认键：

| 动作 | 现在 | 新默认 | 理由 |
|---|---|---|---|
| 复制这一组 | 无 | Ctrl+D | 常见"复制一份"键，本程序未占用 |
| 设置开始和结束时间… | 无 | Ctrl+T | 未占用；T 单独仍是自由变换 |
| 整体平移… | 无 | Ctrl+Shift+T | 和设置时间相邻 |
| 隐藏／取消隐藏 | 无 | Ctrl+H | 审片常用 |
| 标记待复查／取消标记 | 无 | Ctrl+M | 同上 |
| 导出发布用 ASS… | 无 | Ctrl+E | 常见导出键 |
| 菜单栏隐藏时弹出菜单 | 只有 Alt+E | Alt+各菜单助记键 | §3.12 |

这些键在文本框（QLineEdit／QPlainTextEdit／QTextEdit）里是否被 Qt 自带键占用，在 U5 用真实按键测试；被占用的键改为「无默认键」，在说明书写明，不另找键。
曾考虑"编辑模式也用 Z／X 补行"：Z／X 在观剧模式是就地补行，在编辑模式会弹对话框，同一个键行为不同，**不采用**。

观剧模式的 Z／X 是"就地编辑翻译／原文"（对白缺该轴时先补空白行），和编辑模式的「补上原声／翻译…」对话框是**不同的动作**：注册表里分别是 `watch.edit_translation`（Z）、`watch.edit_original`（X），补轴对话框没有默认键。Alt+T 的动作名是「自由变换这一行」。

### 9.5 「快捷键」对话框（工具 → 快捷键…）
- 标题「快捷键」；左上搜索框（占位文字「搜索命令或按键」，按名字或键搜索）。
- 表格按场景分组（「编辑界面」「观剧模式」「K 轴」「弹窗内部（不能改）」），列：「命令」「快捷键」「默认」。
  命令名就是菜单名，**在子菜单里的项前面加上子菜单名**（如「自动 K 轴 → 这一句」「导出 → 发布用 ASS…」），避免几个「这一句」分不清；同一动作在不同菜单出现只列一次。
- 改键：双击「快捷键」格或点「改键…」→ 进入录制状态（格子显示「请按新的快捷键…」，Esc 取消，Backspace 清空＝不用快捷键）。录制用 QKeySequenceEdit 或等价控件，**输入法组合期间不录制**。
- 冲突：同一场景（或会同时生效的场景：`watch` 与 `main` 对没有单独绑定的动作算同一场景）内两个动作同键时，两行标红，底部写「Ctrl+D 已用于「复制这一组」」，「确定」不可点；
  不同场景同键（例如 `k` 场景的 Del 和 `main` 的 Del）允许，按 §9.2 优先级生效，表格里灰字注明「K 轴里优先」。
- 保留键：录制到保留键时提示「F1 是保留键，不能分配」，不接受。
- 按钮：「恢复这一项」「全部恢复默认」（要确认：「把所有快捷键恢复为默认？」）「打开快捷键一览」（说明书 #keys）「确定」「取消」「帮助」。
- 保存：QSettings `shortcuts/version=1`，`shortcuts/<场景>/<动作 ID>` = 以 `;` 分隔的 `QKeySequence.PortableText`；空字符串＝不用快捷键；没有这一项＝默认。**不写进工程文件。**
- 「确定」后立即生效（菜单右侧的键、悬停提示、工具栏提示同步更新），重启后保留。设置里出现未知动作 ID 时忽略，不报错。

## 12. Sol 批次与验收

总原则：
- **先做不改外观的重构，再改结构**，前两批用"外观和行为完全不变"验收。
- 每个**发布批次**（有用户可见变化、要升版本号的）在同一批里更新说明书对应章节、快捷键一览、版本记录、F1 章节（AGENTS.md）。一个发布批次可以用同一个 `plan_ref` 分两次 Sol 运行完成，但第一次运行结束时不交给用户试用。

## 14. U9：对话框按钮统一（2026-10-18 用户要求开做）

盘点：53 个对话框类。多数用 QDialogButtonBox（Windows 下「帮助」在最右）；一部分手工排 QPushButton，顺序各不相同；QMessageBox 的「帮助」被加成单独一整行、横跨整个宽度。

规则（Claude 决定，沿用 Windows 习惯和 QDialogButtonBox 的 Windows 排法）：
1. 按钮放在对话框底部一行，靠右。从左到右：辅助操作（如「全部恢复默认」「打开快捷键一览」，放最左并和右侧主按钮之间留空）｜主操作（「确定」「保存」「应用」「导出」等，默认按钮）｜「取消」或「关闭」｜「帮助」。
2. 「帮助」永远在最右、同一行、普通宽度，不是默认按钮，点它只打开说明书对应章节，不关闭对话框。QMessageBox 也一样（不再整行横跨）。
3. 文字统一中文：「确定」「取消」「关闭」「帮助」；不出现英文 OK／Cancel（Qt 标准按钮没有翻译时要显式设中文）。
4. Esc＝取消／关闭；Enter＝默认按钮。删除、移除等不可撤销的操作永远不是默认按钮。
5. 进度对话框只有「取消」一个按钮（加「帮助」时同样放最右）。
6. 只调整按钮的位置、文字、默认状态；对话框内容、尺寸逻辑和行为不变。
7. 走查发现一并修：「快捷键」对话框里「快捷键」「默认」两列太窄，多个键被截断 → 两列按内容宽度显示，「命令」列占剩余宽度。

验收：一个统一的小工具函数（例如 views 下的公共模块）负责按规则排按钮和加「帮助」；所有对话框改用它；测试扫描所有对话框类的构造路径（能实例化的直接实例化检查按钮顺序和文字，不能实例化的用源码扫描规则），确认没有英文按钮、帮助在最右且不关闭、删除类不是默认按钮。
