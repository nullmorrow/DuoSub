# 自动调轴（字幕和视频版本对不上）— 设计

状态：**已定（2026-10-04）**，按第 7 节实施。第 1 节是实测，第 2–6 节是最初的草案，**以第 7 节为准**。
来源：HANDOFF TODO“自动调轴”；用户 2026-10-04：下载的字幕和视频版本不一样（少女革命、巌窟王），
先对应翻译和原文，再按原文和视频的音频自动调轴；要有几种匹配模式，推荐一种，其他的也能选。

## 1. 实测：两部作品到底差在哪（只读分析，脚本不入库）

方法：把一条时间轴（字幕的“有字/没字”，或视频音频里的人声强弱）和另一条在 2 分钟的窗口里互相关，看每个窗口要挪多少。

**少女革命（视频 BD）**
- Netflix 日文 CC 对 BD 中文成品（E06–E15 每一集都一样）：前半集晚约 +0.45～+0.65 秒；**片中断点（约 10 分钟处）之后突然差约 −15.5 秒**（Netflix 版的断点长度不同），后半集一直保持。
- E16/E17：Netflix 日文对**视频音频**：前半 −0.44 秒、后半 +15.58 秒，整段很稳——音频能直接看出来。
- 中文（字幕组）对视频音频：前半集也在慢慢漂（+0.1 → +0.6 秒，像 23.976/24 帧率的速度差）。也就是说**中文也不完全对**，哪一边准不是固定的。
- 打斗/插曲段（音乐盖住人声）有几个窗口算错（离群值），要靠稳健拟合和别的参照补。

**巌窟王（视频 BD，中文来自 DVDRip 字幕组，日文来自 Cleo 的 srt）**
- 中文对视频音频：整体差 0.1～0.2 秒，后半集和前半集差一点（你在 E02 后半手动挪了约 0.23 秒）。
- 日文（Cleo）对视频音频：约 −0.6～−1.3 秒，而且行的时间本身很粗（很多行是整 2 秒一段），窗口质量低——**只平移不够，还需要逐行贴合人声**。
- E01 成品里中文时间没改、日文用了中文的时间：这一部“中文为准、日文跟中文”最省事。

结论：要处理三种情况——整体差一点；片中断点前后差得不一样（跳变）；每段里有速度差（漂移）。另外逐行的开始/结束要能贴近人声。
音频是唯一的“真相”，但音乐段不可靠；另一种语言的字幕在音乐段常常更可靠（歌词、旁白）。

## 2. 匹配模式（参照 × 方式）

**参照（按什么对）**
- A. **视频音频（人声）**——推荐。不依赖另一份字幕准不准。
- B. **另一种语言的字幕**——那一份已经对的时候最稳（巌窟王的中文）；不需要解码音频。
- C. **两者一起**——以音频为主，音频不可靠的窗口（音乐、静音、离群）用另一份字幕补。

**方式（怎么挪）**
1. **整体平移**：一个数。
2. **分段平移**：在片中断点、长空白处分段，每段一个数（少女革命的 −15.5 秒跳变）。
3. **分段平移 + 速度**（推荐默认）：每段一个数加一个速度（处理 23.976/24/25 帧率差导致的慢慢漂）。
4. **逐行贴合人声**（可选，在 1–3 之后）：每一行的开始/结束在附近（默认 ±0.6 秒）找最近的人声起止。
   选项：只调开始 / 开始和结束 / 保持原时长。没有人声的行（屏幕字、书信、标题、`\pos` 的行）**不贴合**，只跟着分段映射走。

推荐默认：**参照 C + 方式 3**，逐行贴合默认关闭（打开时默认“开始和结束”）。每个选项都能在对话框里换，换了马上重算预览。

## 3. 在流程里的位置

1. **合并前，按来源校准**（主路径）：添加一集 / 合并时，对某个来源（例如 Netflix 日文）点「按视频校准时间…」，
   算出这个来源的**时间映射**（分段 + 速度），存进 `episode.json` 的来源条目。原字幕的字节、原时间都不变；合并、预览、导出用映射后的时间；
   原文面板同时显示原时间和映射后的时间。这样配对（对齐要用时间）也会更准。
2. **合并后，按语言重新调轴**：集 → 「自动调轴…」，选语言（原声 / 翻译 / 两者）、参照、方式，预览后应用，一步撤销。
   - 你手动调过的行（时间和来源映射后的时间不同）、确认过的组：默认不动（可勾选）。
   - 配对的行：默认“两种语言同一时间”（和你的成品一致，323/324 行同时间）——调好一种语言后，另一种可以选「跟着配对的行走」（模式 B 的特例，就是你说的“先对应翻译和原文，再通过原文调轴”）。
   - K 轴拍跟着行一起平移/缩放（和平移 Group 一样）。
3. **OP/ED/插曲**：重复段落库（E）已经能按音频找到位置，可作为强锚点；歌曲行不做“贴合人声”。

## 4. 预览和确认

- 对话框上半：一条时间线（整集），画出每个窗口算出的偏移（点）和拟合的分段线；离群点灰色；每段写「{开始}–{结束}：{±毫秒}，速度 {×1.0010}，可信度 {高/中/低}」。
  可以拖动分段点、删掉一个分段点、把某段改成手填的数（人工决定优先）。
- 下半：逐行列表「原时间 → 新时间（±毫秒）」，按段分组；低可信度的段默认不勾。可以试听（跳到这一行播放）。
- 应用：一步撤销；来源映射存起来，以后重新合并也用它。

## 5. 不做 / 以后

- 不用语音识别模型、不下载模型（只用现有音频特征：频谱、起音）。人声识别靠频带能量，可能被音乐干扰——所以有参照 C 和可信度。
- 以后可加：按画面切换（关键帧）辅助找断点；把用户成品的“提前量”（字幕比人声早多少）学成默认值。

## 6. 需要用户确认的选择

1. 推荐默认是不是 **参照 C（音频为主，字幕补）+ 方式 3（分段 + 速度）**，逐行贴合默认关？
2. 先做 **合并前按来源校准**（新集从一开始就对），合并后的「自动调轴」第二批再做——这个顺序可以吗？
3. 逐行贴合时，字幕比人声提前多少开始、延后多少结束（例如提前 0.1 秒、延后 0.3 秒）？可以从你的成品（巌窟王 E01）里量出来当默认值。
4. 验收数据：巌窟王 E01（成品 + 视频）当“标准答案”，少女革命 E16/E17（视频 + Netflix 日文 + 中文）看跳变和漂移。可以吗？（都只读）

## 7. 定案（用户 2026-10-04 的回答）

用户：默认按推荐（音频为主、字幕补 + 分段平移加速度，逐行贴合默认关）；**自动调轴是一个一键功能**；
逐行贴合的提前/延后由 Claude 建议默认值，并能手动改；验收数据按第 6 节；**用户手调的成品不一定准**，特别是画面上的纯文字翻译不一定对应语音。

### 7.1 一键（界面文字照抄）
- 集菜单：「自动调轴（按视频音频）」。对已经合并的一集，一键完成：按视频音频算出整集的时间映射，**直接应用**，一步撤销。
  （合并本来就会跟踪两份字幕之间的时间差来配对，所以不需要在合并前另做一步；一集里的两种语言按组一起挪。）
- 完成后弹出结果框（标题「自动调轴」）：
  - 「已调整 {n} 组（{m} 行）。Ctrl+Z 可以撤销。」
  - 每一段一行：「{开始}–{结束}：{±秒} 秒{，速度 ×{倍率}}（可信度 {高/中/低}）」，例：「0:00:00–0:10:31：−0.44 秒（可信度 高）」「0:10:31–0:23:40：+15.58 秒（可信度 中）」。
  - 没动的（有才显示）：「{k} 组你确认过或手动调过时间，没有动。」「{j} 组所在的段可信度低，没有动。」
  - 按钮：「撤销」「详细设置…」「关闭」。
- 没有视频或音频还没读完：「音频还在读取，读完后再试。」/「这一集没有视频，不能按音频调轴。」
- 找不到可信的映射（例如整集几乎没有人声）：「没有找到可信的时间差，什么都没改。」
- 已经对得上（没有要改的组，映射可信）：「字幕和视频已经对得上（最大偏差 {X} 秒），什么都没改。」
- 某一行正好跨在片中断点上（断点切在一行里面）：这一组不动，计入“可信度低，没有动”的数量。
- 映射给某一组的改动不到 40 毫秒（约一帧）时这一组不动（实测巌窟王 E01/E03 只差 2–9 毫秒，原先会把整集几百组都挪几毫秒）。

### 7.2 「详细设置」对话框（其他模式都在这里）
- 标题「自动调轴 — 详细设置」。打开时先撤销刚才的一键结果，按新设置重算预览，「应用」后是新的一步撤销。
- 「参照」：视频音频（推荐）/ 按原声字幕原来的时间 / 按翻译字幕原来的时间。
  - 视频音频：音乐盖住人声、可信度低的窗口，用相邻可信的段推算；如果某一份字幕原来的时间在相邻可信段里和音频一致，就用它补这一段。
  - 按某一份字幕原来的时间：每组用这一种语言来源里的原时间；这一组没有这种语言的，按相邻组的时间差推算（不用音频）。
- 「方式」：整体平移 / 分段平移 / 分段平移 + 速度（推荐）。
- 「逐行贴合人声（实验）」（默认关）：「只调开始 / 开始和结束 / 保持原时长」；「比人声提前 {秒} 开始」「比人声延后 {秒} 结束」（默认值见 7.3b：0.27 / 0.00，可改，记住上次的值）。
  不贴合的行：屏幕字、注释、带位置标签的行、歌曲行、附近没有人声的行——它们只跟着所在的段一起挪。
- 「也调整确认过的组和手动调过时间的行」（默认不勾）。
- 上半：分段表（开始、结束、时间差、速度、可信度），可以改某一段的时间差、删掉一个分段点；下半：逐组「原时间 → 新时间（±毫秒）」，低可信度的段默认不勾，可以试听。
- 按钮「应用」「取消」「帮助」。

### 7.3 默认值和保护
- 推荐默认：参照 视频音频，方式 分段平移 + 速度，逐行贴合 关。
- 提前/延后默认：先按常见习惯 **提前 0.15 秒、延后 0.30 秒**；实施时从巌窟王 E01 成品的“有人声的行”量一次，量出来差得多再调整默认值（报告里写实测）。
- 手动调过时间：从这个版本起，你在波形上打轴、拖线、`[` `]` 微调、改时间的行会记一个“手动调过”的标记；以前的工程没有这个标记，只按“确认过的组”保护。
- K 轴拍跟着行一起平移 / 按速度缩放；原字幕的字节和原时间永远不变。

### 7.3b 实测后的调整（Claude，A1/A2 结果）
- 估计用的“字幕对人声”相关有约 160 毫秒的固定偏差，按巌窟王 E01 成品校正（“0”= 像你的成品那样的时间）。
- **逐行贴合效果有限**（只靠频带能量判断人声起止）：E01 中文本来就对，贴合后反而差 0.14 秒；Cleo 日文差近 1 秒，超出搜索范围也帮不上。
  所以逐行贴合保持默认关，界面写「逐行贴合人声（实验）」；默认值改成从你的 E01 成品量出来的：**比人声提前 0.27 秒开始、延后 0.00 秒结束**（还是可以改）。
- 速度只接受真实存在的两类：时钟差（±0.15% 以内，例如 24/23.976）和 PAL（约 ±4.2%），而且要有至少 5 分钟可靠证据、明显改善才用；其他一律按 1.0。

### 7.3c 时间轴质量（用户：少女革命的中文字幕时轴 = “糟糕”的门槛）
- 两项分开说：**整体偏差**（一键能纠正的部分：整集最大偏差）和 **逐行整齐度**（纠正整体偏差后，各段之间还剩多少不一致）。
- 逐行整齐度：好（≤ 0.08 秒）/ 一般（≤ 0.2 秒）/ 差（> 0.2 秒，或一半左右的窗口找不到可靠的对应）。
  实测：巌窟王中文 0.02–0.05 秒（好）；少女革命 Netflix 日文 0.04–0.06 秒（好，只是整体差 15 秒）；Cleo 日文 0.16–0.35 秒且大量窗口不可靠（差）；
  少女革命中文 0.6 秒以上（差——就是用户说的门槛）。
- 结果框加一行：「时间轴质量：整体偏差最大 {X} 秒（已纠正）；逐行整齐度 {好/一般/差}」。为“差”时再加一句：
  「这一集的字幕本身时间就不整齐（和少女革命的中文字幕差不多或更差），自动调轴只纠正整体偏差，个别行还要手动调。」
- ~~自动提示（状态栏）~~ → **改为询问（用户 2026-10-04：不要让人去注意 10 秒后就消失的提示，要给用户选择）**，见 7.5。

### 7.5 音频读完后的询问（取代状态栏提示；也取代重复段落库 PASSAGES.md 5.1 的状态栏提示）
- 一集的音频读完后检查两件事：整体偏差 ≥ 0.15 秒且可信度不低；库里有这一集还没套用的重复段落。有任何一件就**询问一次**（同一集在这次打开期间只问一次）。
- **不打断操作**：正在打字、有对话框或弹窗开着、正在自由变换或按 K 打拍、正在播放时先不弹，等停下来（暂停、关掉对话框）再弹。切到别的集就不再问上一集。
- 对话框标题「这一集可以自动处理」，内容按找到的列出：
  - 「字幕和视频差约 {X} 秒{（片中断点前后不同）}。」（有分段时加括号里的话）
  - 「找到重复段落：{名称列表}。」（名称格式同 PASSAGES.md 5.1）
  - 最后一行：「要现在处理吗？处理后都可以 Ctrl+Z 撤销。」
- 按钮（只显示有用的）：「自动调轴」「套用重复段落…」「先不处理」；勾选框「这一集不再询问」（记在本机设置里，按工程和集记住，不改工程文件）。
  - 「自动调轴」= 菜单的一键自动调轴（结果框照常出来）；如果也找到重复段落，结果框关闭后接着打开「查找并套用重复段落」对话框。
  - 「套用重复段落…」= 打开查找并套用对话框。
- 观剧模式（F10/F11）里同样询问（对话框在全屏上方），处理完回到原来的模式。
